# 核心术语表

这份术语表优先解释 Agent 开发里最容易混淆、但又最关键的概念。后续专题文档会继续展开。

## Prompt

Prompt 是给模型的输入指令与上下文组织方式，不只是“提问句子”，还包括：

- 任务说明
- 角色设定
- 约束条件
- 输出格式
- 示例
- 外部上下文

Prompt 决定模型如何理解任务，但不等于完整 Agent。

## Agent

Agent 是面向目标执行任务的 AI 系统，通常具备：

- 决策能力
- 工具调用能力
- 状态维护能力
- 多步执行能力

它的关注点是“完成任务”，不是“生成一段回答”。

## Tool

Tool 是 Agent 可以调用的外部能力接口，例如：

- 搜索
- 数据库查询
- API 调用
- 浏览器操作
- 代码执行

Tool 的设计质量，直接影响 Agent 的稳定性和成功率。

## Skill

Skill 通常指可复用的高层能力封装。它往往不只是一个工具，而是一组固定流程、知识、规则或工具组合。

可以把它理解成：

- 给 Agent 复用的“能力模块”
- 针对某类任务的“最佳实践封装”

## Hook

Hook 是在系统生命周期中的特定时机注入逻辑的机制，常见触发点包括：

- 调用模型前
- 调用工具前后
- 状态写入前后
- 任务结束时
- 失败重试时

Hook 适合做日志、审计、监控、改写、拦截和权限控制。

## Harness

Harness 可以理解为 Agent 的“测试与运行基座”。它重点解决的不是推理本身，而是：

- 如何稳定重放任务
- 如何批量跑评测
- 如何对比不同版本
- 如何记录中间过程
- 如何做回归验证

如果 Prompt 是输入层，Harness 更像验证层和实验层。

## Loop

Loop 是 Agent 的控制循环，也就是它如何一轮一轮地：

- 读取状态
- 进行判断
- 选择动作
- 调用工具
- 更新结果
- 决定继续还是结束

没有 Loop，就很难称为真正的 Agent。

## Memory

Memory 是 Agent 保存和利用历史信息的机制，常见包括：

- 短期对话上下文
- 当前任务状态
- 长期用户偏好
- 外部知识检索结果

Memory 不等于“把所有历史都塞进上下文”，重点是有选择地保留和调用。

## Workflow

Workflow 是任务编排结构，强调步骤、状态流转和节点连接。它比单纯的 Loop 更显式，适合：

- 长流程任务
- 多分支逻辑
- 多角色协作
- 人工审批节点

## Guardrails

Guardrails 是防止 Agent 出错、越权、失控的约束机制，包括：

- 步数限制
- 工具权限限制
- 输出校验
- 敏感操作确认
- 失败熔断

## Eval

Eval 是对 Agent 行为进行系统化评估的方法，重点不是“模型说得像不像”，而是：

- 任务是否完成
- 工具是否调用正确
- 结果是否可验证
- 不同版本是否退化

## Multi-Agent

Multi-Agent 是多个 Agent 协作完成任务的架构。只有当任务确实存在：

- 明确分工
- 上下文隔离需求
- 不同决策角色

时，多 Agent 才值得引入。否则很多问题用单 Agent 更稳。
