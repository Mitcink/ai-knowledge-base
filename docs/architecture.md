# 技术架构说明

## 1. 目标

这个项目的目标不是做一个只会演示的 RAG demo，而是做一套你可以长期维护、部署在服务器上、通过 GitHub 持续演进的个人知识库。

## 2. 核心选型

### 后端

- `FastAPI`
- 原因：接口定义清晰，文档自动生成，适合文档上传、检索和问答 API

### 向量库

- `Qdrant`
- 原因：Docker 部署方便，适合个人项目，后续支持更强的混合检索

### 前端

- `Streamlit`
- 原因：第一版开发速度快，适合你快速验证知识库是否“真能用”

### 模型接入

- OpenAI 或兼容 OpenAI API 的服务
- 原因：便于快速稳定落地，不需要第一版就自己部署模型

## 3. 系统流程

### 导入流程

1. 文档进入 `data/raw/` 或通过 Web 上传
2. 解析文本内容
3. 按长度和重叠切块
4. 调用 embedding 接口生成向量
5. 写入 Qdrant，并附带 metadata

### 查询流程

1. 用户输入问题
2. 生成查询向量
3. 从 Qdrant 召回候选 chunk
4. 用关键词重叠做轻量 rerank
5. 拼接上下文
6. 调用大模型生成答案
7. 返回答案和引用来源

## 4. 目录职责

### `app/api`

- 对外提供健康检查、导入、查询接口

### `app/services`

- `document_loader.py`：文档解析
- `chunking.py`：文本分块
- `embeddings.py`：embedding 调用
- `vector_store.py`：Qdrant 读写
- `rag_service.py`：RAG 编排逻辑

### `scripts`

- 批量导入资料，适合首次初始化索引

### `ui`

- 提供简单交互页面，方便日常使用

## 5. 为什么这版适合第一次做

- 学习曲线平缓
- 每一层都能独立调试
- 服务器部署简单
- 后续可以平滑替换组件

## 6. 后续升级路线

### 检索升级

- 从“向量召回 + 关键词加权”升级到：
  - Qdrant 稀疏向量
  - BM25
  - 专门的 reranker 模型

### 数据源升级

- 增加网页导入
- 增加 Notion 导出
- 增加 Obsidian 同步
- 增加 OCR PDF

### 产品化升级

- 用户登录
- 文档管理后台
- 历史会话
- 收藏回答
- 标签体系

## 7. 你应该如何维护它

- 文档统一归档到固定目录
- 定期批量导入新增文件
- 遇到回答不准时，优先检查 chunk 和 metadata
- 版本更新走 GitHub PR 或 commit 说明
