# Agent 知识库建设路线图

本文档定义这个知识库的分批建设方式，也作为你后续学习和搭建 Agent 的主线。

## 总目标

把这个仓库逐步建设成一套面向 Agent 开发全链路的知识库，最终同时满足三件事：

- 能查：能快速找到某个概念、模式、框架或实现方法
- 能学：能沿着路线逐步掌握 Agent 工程
- 能做：能据此搭建、测试、迭代一个真实可运行的 Agent 系统

## 分批计划

### 第 1 批：地基

目标：统一概念和学习路径，避免后续材料堆叠失控。

产出：

- 知识库总览
- 路线图
- Agent 入门
- 核心术语表
- 资料筛选与沉淀原则

### 第 2 批：Agent 最小闭环

目标：理解一个 Agent 为什么能跑起来。

重点主题：

- Prompt 与上下文工程
- Tool calling
- Planning / ReAct / Act-only / Plan-and-execute
- Memory 与状态
- Loop 与终止条件

建议实践：

- 用一个 LLM + 2 到 3 个工具实现单 Agent MVP

### 第 3 批：工程化搭建

目标：从 demo 走向可维护系统。

重点主题：

- Skill 设计
- Hook 与生命周期
- Workflow / Graph 编排
- 失败重试、超时、回滚
- 权限边界与安全控制

建议实践：

- 为 Agent 增加日志、状态、重试、人工兜底

### 第 4 批：评测与稳定性

目标：建立“不是看感觉，而是可验证”的 Agent 研发方法。

重点主题：

- Harness
- Eval 数据集
- 回放与对比
- 离线评估与线上观测
- 成本、延迟、成功率指标

建议实践：

- 为一个 Agent 任务集建立自动回归测试

### 第 5 批：框架与生态

目标：把主流框架和模式放回统一认知框架里。

重点主题：

- LangChain
- LangGraph
- AutoGen
- MCP
- Dify / Coze
- OpenAI Agents / Responses / tool use 相关能力

建议实践：

- 用至少两种框架实现同一个任务，对比抽象层次和维护成本

### 第 6 批：真实业务场景

目标：沉淀“可商用”的设计与实现经验。

重点主题：

- 客服 Agent
- 数据分析 Agent
- 浏览器操作 Agent
- 运维 Agent
- 多系统协同 Agent

建议实践：

- 选择一个具体业务场景做端到端案例

## 推荐学习顺序

如果你希望一边整理一边学，建议按下面路径推进：

1. 先弄懂 Agent 的定义、组成和最小闭环
2. 手写一个最简 Agent，不依赖重框架
3. 再看 Skill、Hook、Harness、Workflow 这些工程化概念
4. 最后再引入具体框架，不要反过来从框架学概念
