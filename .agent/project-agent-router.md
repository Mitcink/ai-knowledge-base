# 项目路由协调

## 目标

把一个需求快速拆成明确分工，避免多人都能做、结果没人真正负责。

## 默认团队编制

- 前端 2 人：界面工程师、应用工程师
- 后端 2 人：接口工程师、平台工程师
- 测试 2 人：测试策略工程师、自动化工程师
- 产品 1 人：产品经理
- 技术负责人 1 人：技术负责人
- 交付 1 人：交付发布经理

## 路由规则

- 需求还模糊、验收不清、范围摇摆：优先给 `$product-manager`
- 页面、组件、样式、响应式、交互细节：优先给 `$frontend-ui-engineer`
- 前端状态、流程、表单、数据交互：优先给 `$frontend-app-engineer`
- 接口、鉴权、校验、业务逻辑：优先给 `$backend-api-engineer`
- 模型、任务、缓存、观测性、稳定性：优先给 `$backend-platform-engineer`
- 测试范围、回归重点、验收路径：优先给 `$qa-test-engineer`
- 自动化测试、夹具、CI、质量门禁：优先给 `$qa-automation-engineer`
- 架构边界、大改造、跨模块方案：优先给 `$tech-lead-architect`
- 上线节奏、回滚、环境准备、发布风险：优先给 `$delivery-release-manager`

## 输出要求

给出以下内容：

- 主负责人
- 协作角色
- 为什么这么分配
- 第一批检查点
- 验证重点
